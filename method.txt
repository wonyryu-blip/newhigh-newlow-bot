------------------------------------------------------------------
1단계. 데이터 접근 경로 조사
------------------------------------------------------------------

핵심 결론: "신고가/신저가 리스트"를 그대로 떠먹여주는 완전 무료 공식 API는
찾기 어렵고, 대부분 "일별 시세 원자료"를 받아서 직접 계산하는 방식이
가장 현실적이고 안정적입니다. 조사한 경로는 다음과 같습니다.

[A] pykrx (오픈소스 파이썬 라이브러리) — ★ 1순위 추천
  - https://github.com/sharebook-kr/pykrx , https://pypi.org/project/pykrx/
  - KRX(한국거래소) 정보데이터시스템을 스크래핑하는 방식으로 동작하는
    무료 오픈소스 라이브러리. pip install pykrx로 즉시 사용 가능.
  - get_market_ticker_list() : 코스피/코스닥 전 종목 티커 목록 조회
  - get_market_ohlcv_by_date() / get_market_ohlcv() : 특정 종목 또는
    특정 일자 전종목의 시가/고가/저가/종가/거래량(OHLCV) 조회
  - 장점: 무료, 전종목 커버, 60일/52주 기준을 내가 원하는 대로
    (종가 기준 vs 장중 고가·저가 기준) 직접 계산할 수 있어 가장 유연함.
  - 단점: 공식 API가 아니라 스크래핑 기반이라 KRX 사이트 구조가
    바뀌면 깨질 수 있음. 짧은 시간에 너무 많이 요청하면 KRX 서버가
    일시 차단할 수 있어 요청 사이 딜레이(예: 1초)가 필요.
  - 계산 방법: 코스피+코스닥 전 종목(약 2,500개 이상)에 대해 최근
    60거래일 / 최근 1년(약 252거래일, 또는 달력 기준 364일) 구간의
    고가·저가를 구해서, 당일 종가(또는 고가/저가)가 그 구간의
    최고/최저를 갱신했는지 비교하는 로직을 직접 작성해야 함.
  - 최초 1회는 전 종목의 과거 1년치 데이터를 수집해 로컬에 저장
    (csv 또는 sqlite)해두고, 이후 매일은 "전일자 신규 데이터만"
    추가 수집해 롤링 윈도우로 최고/최저를 갱신하는 구조로 짜면
    매일 아침 실행 시간을 크게 줄일 수 있음.

[B] 한국투자증권 KIS Developers (공식 증권사 Open API)
  - https://apiportal.koreainvestment.com/apiservice
  - 국내주식 > 순위분석 카테고리에 "국내주식 신고/신저근접종목 상위"
    라는 API가 실제로 존재하는 것을 확인함.
  - 개인도 무료로 개발자 계정을 만들고(실전/모의투자 계좌 연동),
    REST API 인증키(App Key/Secret)를 발급받아 사용 가능.
  - 장점: 공식 증권사 데이터라 신뢰도가 높고, "근접" 종목까지
    순위 형태로 바로 제공해 직접 계산할 필요가 줄어들 수 있음.
  - 단점(확인 필요): 이 API가 정확히 "60일" 기준과 "52주" 기준을
    구분해서 지원하는지, 코스피+코스닥 전종목을 한 번에 커버하는지는
    로그인 후 API 문서(요청 파라미터: 기간구분코드 등)를 직접 열어
    확인해야 함 — 로그인 영역이라 이번 조사에서는 문서 원문까지는
    확인하지 못함. pykrx 방식의 검증(대조)용으로 병행 사용 추천.
  - GitHub 샘플 코드: https://github.com/koreainvestment/open-trading-api

[C] 네이버금융 / 다음(카카오페이증권) 웹페이지 크롤링
  - 네이버금융(finance.naver.com)에 신고가/신저가 관련 화면이
    있는 것으로 알려져 있으나, 이번 조사에서는 접속이 차단되어
    정확한 URL과 "코스피+코스닥 전 종목, 60일/52주 구분 제공 여부"를
    직접 확인하지 못함(추가 확인 필요).
  - 다음(Daum) 금융도 유사 서비스가 있었으나 현재 카카오페이증권으로
    통합된 상태.
  - 공식 API가 아닌 크롤링이라 이용약관 위반 소지, 페이지 구조 변경 시
    깨질 위험이 있어 A안(pykrx)보다 우선순위를 낮게 둠.

[D] KRX Data Marketplace (한국거래소 공식 Open API)
  - https://openapi.krx.co.kr/
  - 회원가입 → 인증키 신청 → API 서비스 이용이라는 정식 절차가 있는
    한국거래소 공식 유료/무료 혼합 오픈API 마켓플레이스.
  - "데이터 구입" 메뉴가 있어 유료 데이터셋이 섞여 있을 가능성이 높고,
    신고가/신저가 세부 상품이 있는지는 목록을 더 파봐야 함
    (문의처: krxdata@krx.co.kr).
  - 공공기관 공식 채널이라 가장 신뢰도가 높지만, 비용 구조 확인이
    선행되어야 해서 2순위로 둠.

[E] 공공데이터포털(data.go.kr) — 금융위원회 제공 API
  - "금융위원회_주식시세정보" (data.go.kr/data/15094808/openapi.do)
  - "금융위원회_KRX상장종목정보" (data.go.kr/data/15094775/openapi.do)
  - 공공데이터포털 계정으로 무료 인증키 발급 후 사용 가능한
    일별 시세/상장종목 기본정보 API. A안(pykrx)과 마찬가지로

  - pykrx가 막히거나 불안정할 경우의 대체/이중화 경로로 적합.

▶ 접근 경로 결론

2단계. 매일 아침 결과를 만들어내는 방법 (스케줄링) 조사
------------------------------------------------------------------

주의사항: 아침 8시 시점에는 당일 장이 아직 시작 전(코스피/코스닥 개장
09:00)이므로, "전일(직전 거래일) 종가 기준"으로 계산한 결과를 받게 됨.
이 점을 사용자가 이미 인지하고 있는지 확인 필요.

조사한 스케줄링 방법:

[a] 로컬 PC + Windows 작업 스케줄러(Task Scheduler)
  - 매일 07:50 KST에 python 스크립트를 실행하도록 등록.
  - 장점: 설정이 간단하고 무료.
  - 단점: PC가 꺼져 있거나 절전 모드면 실행되지 않음 → 매일 아침
    반드시 확인받아야 하는 용도에는 리스크가 있음.

[b] GitHub Actions (cron 스케줄)
  - 저장소의 .github/workflows/*.yml에 schedule: - cron: "50 22 * * *"
    (UTC 기준이므로 KST 07:50 = UTC 전날 22:50) 형태로 등록.
  - 장점: 무료 티어로 충분히 운영 가능, 서버 관리 불필요.
  - 단점: 무료 플랜에서는 실행 시각이 몇 분~십수 분 지연될 수 있음
    (정시 보장 안 됨). 코드가 GitHub 저장소에 있어야 함.

[c] 클라우드 서버리스 (AWS Lambda+EventBridge, GCP Cloud
    Functions+Cloud Scheduler 등)
  - 장점: 안정적이고 시각 오차가 적음, 대부분 무료 티어 범위 내 비용.
  - 단점: 초기 설정(클라우드 계정, IAM 등)이 상대적으로 번거로움.

[d] 리눅스 서버/VPS + crontab
  - 전통적인 상시 서버 방식. 상시 켜진 서버가 있다면 가장 단순하고
    확실함.

[e] Claude Code의 "schedule" 기능(클라우드 예약 에이전트)
  - 지금 이 세션(Claude Code)에서 바로 쓸 수 있는 기능으로, 매일
    지정 시각에 클라우드에서 에이전트를 자동 실행시킬 수 있음.
  - 데이터 수집 → 계산 → 텔레그램 전송까지 한 번에 클라우드에서
    처리 가능해서, 별도 서버/PC 상시 구동이 필요 없다는 게 큰 장점.
  - 다만 매일 반복 실행되는 만큼 비용/토큰 사용이 발생할 수 있어
    실행 빈도와 처리량(전종목 스캔)을 감안해야 함.

▶ 스케줄링 결론
  - "매일 아침 반드시 놓치지 않고" 받아보는 것이 목적이라면, 상시
    켜져 있지 않은 [a] 로컬 PC 방식보다는 [b]/[c] 클라우드 서버리스
    또는 [e] Claude Code 예약 기능이 더 안전함.
  - 처음엔 [a] 로컬 PC로 프로토타입을 검증한 뒤, 안정화되면 [b]나 [e]로
    옮기는 단계적 접근을 추천.

3단계. 텔레그램으로 받아보는 방법 조사
------------------------------------------------------------------

1) 봇 생성
   - 텔레그램 앱에서 공식 봇 @BotFather와 대화 시작.
   - /newbot 명령 입력 → 봇 이름, username 설정 → API 토큰
     (예: 123456789:ABC-DEF1234ghIkl...) 발급받음. 무료.

2) chat_id 확인
   - 생성한 봇과 개인 대화방(또는 알림 받을 그룹)에 아무 메시지나
     한 번 전송.
   - 브라우저로 https://api.telegram.org/bot<발급받은토큰>/getUpdates
     접속 → 응답 JSON에서 chat.id 값을 확인해 본인의 chat_id로 사용.

3) 메시지 전송 코드 (파이썬 예시)
     import requests
     TOKEN = "발급받은 봇 토큰"
     CHAT_ID = "확인한 chat_id"

     def send_telegram(message: str):
         url = f"https://api.telegram.org/bot{TOKEN}/sendMessage"
         requests.post(url, data={"chat_id": CHAT_ID, "text": message})
   - requests만으로 충분하며, 더 복잡한 상호작용(버튼 등)이 필요하면
     python-telegram-bot 라이브러리 사용 가능.

4) 스케줄러와 연결
   - 2단계에서 고른 스케줄러가 매일 아침 파이썬 스크립트를 실행 →
     스크립트 안에서 1단계 로직으로 신고가/신저가 리스트 계산 →
     send_telegram()으로 결과 전송, 이렇게 파이프라인을 연결.

5) 실무 팁
   - 텔레그램 메시지는 1건당 4096자 제한이 있음. 신고가+신저가
     종목이 많을 경우(수십~수백 개) 메시지를 나눠 보내거나, 요약본만
     텍스트로 보내고 전체 목록은 csv 파일로 만들어 sendDocument API로
     첨부 전송하는 방식을 권장.
   - 토큰은 코드에 하드코딩하지 말고 환경변수(.env)로 관리.
   - 스크립트 실행 자체가 실패했을 때(휴장일, API 오류 등)도 에러
     메시지를 텔레그램으로 보내도록 예외 처리를 넣으면 "오늘 왜
     메시지가 안 왔지?"를 방지할 수 있음.

종합 결론 및 추천 실행 순서
------------------------------------------------------------------
1) pykrx로 로컬에서 프로토타입 제작: 코스피+코스닥 전 종목 최근 1년
   OHLCV 수집 → 60거래일/52주 신고가·신저가 계산 로직 검증.
2) 텔레그램 봇 생성 후 수동으로 테스트 메시지 전송해보기.
3) 1)+2)를 하나의 스크립트로 합쳐 로컬에서 하루 수동 실행해보고
   결과물 포맷(어떤 정보를 보여줄지: 종목명, 현재가, 등락률 등) 확정.
4) 안정화되면 GitHub Actions cron 또는 Claude Code 예약 기능(schedule)
   으로 옮겨 "매일 아침 8시(KST)" 자동 실행 확정.
5) 운영 중 예외처리 보강: 휴장일(주말·공휴일) 스킵, KRX 서버 응답
   지연/차단 시 재시도, 신고가/신저가 기준(종가 vs 장중가) 명확화.

참고: "60일"을 거래일 기준으로 볼지 달력일 기준으로 볼지, "52주"를
거래일(약 252일) 기준으로 볼지 달력일(364일) 기준으로 볼지는 통계
관례상 여러 방식이 혼재하므로, 실제 구현 전에 사용자와 기준을
한 번 더 확정하는 것을 권장함.

[추가 조사] 1단계 상세 확인 — B안(한국투자증권 KIS Developers) 실사
조사일: 2026-08-31
==================================================================

사용자가 A안(pykrx 직접 계산) 대신 B안(한국투자증권 KIS Developers
공식 API)으로 진행하기로 결정하여, "코스피·코스닥 전종목의 60일·
52주(달력일 기준) 종가 기준 신고가 경신 종목 리스트"를 이 API로
받을 수 있는지 실제 소스코드 수준까지 파고들어 확인함.
API 인증키/시크릿은 이 폴더의 .env 파일에 저장해둠.

■ 찾은 API
  - 이름: 국내주식 신고/신저근접종목 상위 [v1_국내주식-105]
  - 카테고리: [국내주식] 순위분석
  - TR_ID: FHPST01870000
  - Endpoint: GET /uapi/domestic-stock/v1/ranking/near-new-highlow
  - 출처: KIS 공식 GitHub 샘플
    (examples_llm/domestic_stock/near_new_highlow/near_new_highlow.py)
    https://github.com/koreainvestment/open-trading-api

■ 요청 파라미터 (실제 코드에서 확인)
  - fid_aply_rang_vol   : 적용 범위 거래량 (0:전체, 100:100주 이상)
  - fid_cond_mrkt_div_code : 시장구분코드 (주식은 "J" 고정)

■★ 가장 중요한 한계 — "기간(60일/52주) 선택 파라미터가 없음"
  위 요청 파라미터 목록 어디에도 "기간"이나 "일수"를 지정하는 필드가
  없음. 즉 이 API는 사용자가 60일/52주/연중 중 기준을 골라서 조회하는
  구조가 아니라, 서버(한국투자증권/KRX)가 내부적으로 정해놓은 하나의
  고정 기준(가장 유력하게는 "연중" 또는 이에 준하는 장기 기준, 통상
  "52주 신고가"라고 부를 때 쓰는 기준과 유사할 것으로 추정)으로만
  결과를 내려주는 것으로 보임.
  참고로 일반 증권사 HTS의 "신고가/신저가 종목 검색" 화면(예:
  미래에셋 Kairos [0188], 한국투자증권 HTS [1301] 등)에는 통상
  "5일/10일/20일/60일/250일/연중" 중에서 기간을 고르는 옵션이
  있는 것으로 확인되나, 이번에 찾은 Open API 버전에는 그 옵션이
  파라미터로 노출되어 있지 않음.

  → 즉, 이 API 하나로는 "60일 기준"과 "52주 기준"을 나눠서 받는 것이
    불가능해 보임(적어도 공개된 파라미터 상으로는). 52주(혹은 서버가
    정의한 장기 고정 기준) 리스트는 이 API로 받을 가능성이 높지만,
    정확히 "달력일 기준 364일"과 일치하는지, "연중"(그 해 1월 1일
    이후)을 의미하는 것은 아닌지는 실제 응답을 받아보거나 공식 문서
    (로그인 필요)를 확인해야 확정됨.

■ 60일 기준을 받으려면?
  이 API로 안 되는 경우, 결국 코스피·코스닥 전 종목에 대해 KIS의
  "국내주식기간별시세(일자별)" API
  (examples_llm/domestic_stock/inquire_daily_itemchartprice)를
  종목별로 개별 호출해서 최근 60일치 종가를 받아온 뒤, 오늘 종가가
  그 구간의 최고/최저인지 직접 계산해야 함. 이는 결과적으로
  A안(pykrx)과 동일한 "종목별 반복 호출 + 직접 계산" 구조가 되어버려,
  B안을 선택한 원래 목적(작업량/오류 가능성 축소)이 60일 기준에
  대해서는 완전히 달성되지 않을 수 있음.

  [검증 2] "기간 기준"이 52주인지 실제 데이터로 역산 확인

      - 금양(001570): API 응답 new_hgpr=9900, new_lwpr=9900
        ↔ 외부 데이터: "52주 최고가 9,900원(2026-03-20),
          52주 최저가 9,900원(2026-03-20)" — 정확히 일치.
      - 삼부토건(001470): API 응답 new_hgpr=347, new_lwpr=347
        ↔ 외부 데이터: "52주 최저가와 최고가는 모두 347원" — 일치.
    → 두 종목 모두 독립적으로 정확히 일치. 이 API의 new_hgpr/
      new_lwpr은 "52주 신고가/신저가" 기준으로 계산되는 것이
      사실상 확인됨.
    → 참고: 응답의 hprc_near_rate(고가 근접비율)가 0.00인 종목만

      넓게 잡았는데도 상위권이 대부분 0.00%로 채워진 것으로 보아,
      정렬 자체가 근접비율 오름차순(신고가에 가장 가까운 순)인
      것으로 보임 — 신고가를 "경신"한 종목만 원하면 응답을 받은
      뒤 near_rate==0.00 인 행만 걸러내면 됨.

  [검증 3] 60일 기준 지원 여부
